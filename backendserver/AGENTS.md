- E wallet = withdrawable earnings, D wallet = deposit ledger; E->D swaps are recorded in lo_wallet_swaps (debit E by full amount) plus an E_SWAP lo_deposits credit (amount minus charge), and charge percentages live as PanelPolicy constants so admin settings cannot change them.
- Merchant cashback debits are disabled by default, require an active hashed API key plus member credentials, lock the member row, and use (merchant key, request_id) idempotency; Wallet::service subtracts only confirmed lo_merchant_cashback_debits and never touches E/D wallets.
- Binary tree `?root=` views walk placement_parent_id upward and must reach the caller; overview=1 returns compact authorised topology and details=1 returns only the requested node's full-subtree totals, keeping unrelated members private.
- Join-page usernames are server-generated (signed read-only preview, re-checked under the placement lock); typed usernames are ignored so members can never pick or edit them.
- Commission timing: Commission::processActivation is the instant phase (cashback, direct referral, pools, daily volume); generation and matching happen only in Commission::closeActivation, run by Settlement for finished Dhaka business days, so a payment reversed before midnight never earns matching/generation.
- Legacy rebuilds run server-side through scripts/legacy-import/rebuild_v3.py (cross-database INSERT…SELECT, idempotent) and are checked by verify_v3.py; old-site carry is stored as Major Link carry only and legacy matching counts live in lo_tree.legacy_* so Total/Rank Matching stays one number.
